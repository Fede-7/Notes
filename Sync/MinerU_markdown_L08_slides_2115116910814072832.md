# What a DNS message carries

Queries and replies have the same format: a 12-byte header, then four sections. 

<sub></sub> Header: an identifier copied into the reply, so the client can match answers to questions, plus a set of flags. 

<sub></sub> The flags that matter: authoritative answer, recursion desired, recursion available. 

<sub></sub> Question: the name being asked about, and the type asked for. 

<sub></sub> Answer: the records that answer it. 

<sub></sub> Authority: servers that would know. 

<sub></sub> Additional: helpful records, typically the addresses of the servers just named.

## From IP Addresses to Hostnames

DNS supports reverse resolution, mapping an IP address to a hostname using PTR (Pointer) records in the special DNS namespace in-addr.arpa (for IPv4), organized hierarchically through DNS zone delegations. 

IP: 192.0.2.10 Reverse DNS: 10.2.0.192.in-addr.arpa. 

The dig -x command performs a reverse DNS lookup: 

dig -x 8.8.8.8 +noall +answer 

<sub>•</sub> -x 8.8.8.8: Queries the PTR record associated with the IP address. 

<sub>•</sub> +noall +answer: Displays only the answer section. 

└── arpa. Infrastructure domain └── in-addr.arpa. Reverse IPv4 namespace └── 192.in-addr.arpa. └── 0.192.in-addr.arpa. └── 2.0.192.in-addr.arpa. └── 10.2.0.192.in-addr.arpa. PTR → host.example.com. 

Example result: 8.8.8.8 → dns.google

## DNS Aliasing with CNAME Records

• DNS provides an aliasing service for servers in which complicated/long names (aka canonical) are associated to a more simple/short ones (aka alias). 

• Stable names: Applications use a consistent hostname even when the underlying infrastructure changes. 

• Flexibility: The canonical hostname can change without affecting the public alias. 

• Separation of responsibilities: The alias and its target can belong to different DNS zones managed independently. The domain owner controls the public alias, while the service provider manages the target hostname and its IP address. 

Example: 

www.enterprise.com ↓ CNAME server.provider.net ↓ A 192.0.2.10 

Aliases decouple public service names from infrastructure hostnames. 

## DNS: Load Distribution

• A DNS can be used to perform load distribution among replicated servers (aka, round-robin DNS). 

• Typically, busy sites (e.g., google, amazon, CNN, etc.) are replicated over multiple servers, with each server running on a different end system and each having a different IP address (multiple IP addresses associated with one canonical hostname). 

• The DNS database contains this set of IP addresses. When clients make a DNS query for a name mapped to a set of addresses, the server may rotate the order in which addresses are replied. 

## DNS: Multiple NS vs. Multiple A Records

## Multiple NS Records — DNS Service Availability

• A DNS zone has multiple authoritative name servers. 

• Resolvers can query different authoritative servers. 

• Purpose: Distribute DNS queries and improve reliability. 

example.com. IN NS ns1.provider.net. 

example.com. IN NS ns2.provider.net. 

example.com. IN NS ns3.provider.net. 

## Multiple A Records — Application Load Distribution

• A single hostname maps to multiple server IP addresses. 

• DNS may rotate the order of returned IP addresses (round-robin). 

• Purpose: Distribute application traffic across replicated servers. 

www.example.com. IN A 192.0.2.10 

www.example.com. IN A 192.0.2.20 

www.example.com. IN A 192.0.2.30 

Key difference: Multiple NS records distribute DNS queries; multiple A records can distribute application traffic.

## Summary

• Names are for people and addresses are for the network: the DNS is the translation, and a distributed database. 

• The name space is a tree; a zone is the part of it one administration actually serves. 

• Records are typed — A, NS, CNAME, MX, SOA — and each carries a TTL. 

• Your host asks once, recursively; the local server walks the hierarchy iteratively, one referral at a time. 

• Caching is what makes this affordable, and the TTL is what bounds how long a stale copy may keep answering. 

• What dig prints — flags, answer, authority and additional sections — is the message format.

## Network Layer From Transport to Network

• The job of the network layer is mainly to allow remote hosts to communicate: 

• At the sending host: to take segments from the transport layer, to encapsulate each segment into a datagram, and to send the datagrams into the network. 

• At the receiving host: to receive the datagrams from the network, extracts the transport-layer segments from datagrams, and delivers the segments up to the transport layer. 

• At this level, some of the most important protocols of computer networks works: 

• IP, DHCP, NAT, etc. 

• There are special devices (routers) that works at this level.

# Network Layer Network Layer in Internet

• The network layer is mainly responsible for host-to-host delivery. 

## • What services could be offered along with delivery:

• Guaranteed delivery: a packet sent by a source host will eventually arrive at the destination host. 

• Guaranteed delivery with bounded delay: packets will be delivered and within a specified host-to-host delay bound (for example, within 100 msec). 

• In-order packet delivery: packets will arrive at the destination in the order that they were sent. 

• Guaranteed minimal bandwidth: possibility to specify a minimal bit rate (for example, 1 Mbps) such that, if the rate of the sending host is within it, then all packets are eventually delivered to the destination host. 

• Security: encryption/decryption of all datagrams at the source/destination. 

• Actually, none of these services is generally offered by networks. 

# Network Layer Network Layer in Internet

• Conversely, Internet’s network layer provides just one service, the so called besteffort service. 

• Best-effort service (or best-effort delivery): the network tries its best to deliver a packet from its source to its destination. 

• Packets are neither guaranteed to be received in the order in which they were sent, nor to be received at all. 

• There is no guarantee about delays or minimal bandwidth. 

• Despite its simplicity, the best-effort service model, in combination with good bandwidth have proven to be adequate. 

• For example, applications, such as Netflix and voice-and-video-over-IP, real-time conferencing, Matrix, etc. all works with it. 

# Network Layer Routers in the Network

• The primary role of the network layer is to perform host-to-host delivery, i.e., to move packets from a sending host to a receiving host. 

• This process is performed by routers (network nodes) that are special nodes having multiple incoming/outgoing links. Routers provide two network-layer functions: 

• Forwarding: when a packet arrives at a router’s input link, the router must move the packet to the appropriate output link. It is also possible to: 

a. Block a packet from exiting a router (e.g., if originated from a known malicious host, or destined to a forbidden host).

b. Drop a packet if it is expired. 

c. Duplicate a packet and sent it over multiple outgoing links. 

d. Modify a packet (e.g., to notify congestion, etc.). 

• Routing: to decide the route or path to be taken by packets as they flow from a sender to a receiver. The algorithms that calculate these paths are referred to as routing algorithms.

## Network Layer Routers in the Network

• Forwarding is router-local: input interface to output interface, inside one box. It takes a few nanoseconds, so it is done in hardware. 

• Routing is network-wide: it settles the end-to-end paths. It takes seconds, so it is done in software. 

• Two functions on timescales a billion apart, which is why they are named separately: data plane: forwarding; control plane: routing. 

• Between them sits one data structure, the forwarding table: the control plane writes it, the data plane reads it once per packet. 

• Consequence: a router forwards without knowing the path. It knows only which of its own links is next. 

## Network Layer Routers: Data and Control Planes

## • The job of routers is typically implemented as a two-step (or two-plane) process:

• Forwarding (data or forwarding plane) refers to the router-local action of transferring a packet from an input link interface to the appropriate output link interface. 

• This is a fast operation (typically a few nanoseconds), and thus is typically implemented in hardware. 

• Routing (control plane) refers to the network-wide process that determines the end-toend paths that packets take from source to destination. 

• This is a slower process (typically seconds), and it is often implemented via software. 

• At the data plane we have the forwarding table: a table that associates output links with possible destination addresses. 

• A router forwards a packet by examining the value of one or more fields in the packet’s header. 

• The value stored in the forwarding table indicates the outgoing link interface to which that packet is to be forwarded. 

## Network Layer Routers: Data plane and Forwarding Table

• A router forwards a packet by examining the value of one or more fields in the arriving packet’s header, and then using these header values to index into its forwarding table. 

• The value stored in the forwarding table entry for those values indicates the outgoing link interface at that router to which that packet is to be forwarded. 

• Traditionally the table is computed inside the router, by a routing algorithm talking to those in the other routers. 

• They exchange routing messages; each router ends up with its own local table, and nobody holds the whole picture. 

• How they agree is a subject of its own, and we will return to it.

## Network Layer Routers: Data and Control Planes

• The content of a forwarding table must be determined by collecting information from different routers. 

• This process is implemented using one or more routing tables (control plane) that eventually lead to the creation of the forwarding table (data plane). 

• Creation of routing and (eventually) forwarding tables can be performed in two ways: 

• Decentralised (or distributed): we can have each router endowed with a routing component that communicates with the routing component of other routers (this was the mainstream approach). 

• Centralised: we can have a physically separated (from the routers) remote controller computes that distributes the forwarding tables to be used by routers.

## Network Layer Routers: Why High-Speed Forwarding Requires Hardware

• Take a 100 Gbps input link and a 64-byte datagram. The port has 5.12 ns before the next one may arrive: $6 4 \cdot 8 / ( 1 0 0 \cdot 1 0 ^ { 9 } )$ 

• A router may have multiple input ports operating simultaneously, requiring the forwarding hardware to process packets at a very high aggregate rate. 

• No software gets near those figures, which is why input ports, output ports and fabric are all hardware — the vendor’s own design or bought-in silicon. 

• The routing processor lives at the other end of the scale, on milliseconds and seconds, and can be an ordinary CPU running ordinary code. 

## Network Layer Routers: Different Types

• Routers can differ significantly in size, capacity, and application. 

• Home and small business: typically have a small number of ports and connect local networks to an Internet Service Provider (ISP). 

• Edge routers: operate at the boundary of a network, connecting it to other networks (e.g., an ISP network to its customers or other providers). 

• Core routers: operate within large backbone networks, forwarding high volumes of traffic between different parts of the network. 

• Scalability: high-end routers may support hundreds of high-speed interfaces (e.g., the Juniper MX2020 supports up to 800 × 100 GbE ports, with a system capacity of 80 Tbps).

## Network Layer Routers: Forwarding

• Problem: storing one entry for every possible destination IPv4 address would require up to $( 2 ^ { 3 2 } )$ entries (over 4 billion!). 

• Solution: instead of storing individual IP addresses, forwarding tables use IP address prefixes, which identify groups of addresses sharing the same initial bits. 

• Each forwarding table entry associates a destination prefix with an output interface.

## Network Layer Routers: Forwarding

• This lookup procedure is typically performed on the hardware to be executed as fast as possible (e.g., in nanoseconds for Gigabit transmissions). 

• Embedded memories and advanced table-search algorithms are also involved. 

• Once a packet’s output port has been determined (after lookup), the packet can be sent into the switching fabric. In some devices, packets may also be temporarily queued (buffered) if other input ports are using the fabric. 

• This two-steps operation of looking up a destination IP address (match) and forwarding (action) is called match-plus-action and is performed in many networked devices, such as: 

• Switches: similar action as routers. 

• Firewalls: where the action is to filter out specific incoming packets. 

• Network address translators (NATs): where the action is to rewrite port number of specific incoming packets before forwarding.

## Network Layer Routers: Switching Fabric

• In a switching fabric, switching can be performed in 3 ways: 

1. Switching via memory: ports are considered as I/O devices that write packets on memory cells then the routing process copies the message on the output port as specified by the forwarding table. 

• This approach is slow (need for memory access) and was more common in early routers (which were standard computers). 

2. Switching via a bus: input port transfers a packet directly to the output port over a shared bus (mutex), without intervention by the routing processor. 

• Only one port per time can be served, but this method is often sufficient for routers that operate in small local area. 

3. Switching via an interconnection network: input/output ports connected by a network having cross-points which can be open/close and then redirect the packets. 

• Here multiple packets can be forwarded in parallel. This method is used in several modern routers.

## Network Layer Routers: Switching via memory

• The earliest routers were ordinary computers, and the ports were ordinary $1 / 0$ devices. 

• An arriving packet interrupted the processor, was copied into memory, looked up, and copied out to the output port’s buffer. 

• The packet crosses memory twice. If memory can take B packets per second, the router forwards fewer than B/2. 

• And two packets cannot be forwarded at once even to different ports: one read or write at a time on the shared bus. 

• In more recent shared-memory architectures, input-port hardware performs the forwarding lookup and transfers packets into the appropriate memory buffers, without involving the central CPU for each packet.

## Network Layer Routers: Switching via bus

• The input port hands the packet straight to the output port over a shared bus, with no routing processor in between. 

• It prepends an internal label naming the output port. All ports see the packet; only the one named keeps it, and it strips the label. 

• One packet at a time on the bus: the switching speed of the router is the speed of the bus. 

• Which is often enough. A well-known enterprise router of this kind switches over a 32 Gbps backplane. 

• Simple, cheap, and a hard ceiling.

## Network Layer Routers: Ports

• Input and output ports use buffers to temporarily store packets when they cannot be transferred or transmitted immediately. 

• Input queueing occurs when packets must wait to cross the switching fabric. 

• Output queueing occurs when packets arrive at an output port faster than the outgoing link can transmit them. 

• Buffer overflow: since buffers have limited capacity, excessive queueing can cause packet loss.

## Routers: Ports

• Example: let’s assume to have (1) a router with N input and N output ports, (2) that each port is receiving packets at the same time, and (3) that all input and output lines have the same speed Rline packets per second. 

• Let’s now consider a worst-case scenario in which all packets have to be forwarded to the same port. 

If the switching fabric have a rate (Rswitch) we have: 

• If Rswitch ≅ N Rline, queuing on input ports is negligible as all packets are forwarded in time by the forward fabric, but queuing on the output port is significant as the rate of incoming packets is N times larger than the rate of the 1-port output link. 

• if Rline < Rswitch < N Rline, there is queuing on both ports as input port must wait for the switch fabric while output port must wait for the link. 

• if Rswitch ≅ Rline, there is negligible queueing on output port but significant queuing on the input ports. 

Note: no choice of fabric removes the queueing. It only decides where it happens.

• Head-of-Line (HOL) blocking occurs when a packet at the front of an input queue cannot be forwarded because its desired output port is busy. 

• Since packets in the same input queue are served in FIFO order, all packets behind it must wait, even if their destination output ports are free. 

• Head-of-Line (HOL) blocking occurs when a packet waiting for a busy or contended output port prevents subsequent packets in the same input queue from being forwarded to other available output ports. 

## Network Layer Routers: Output Queueing and Buffer Management

• Even with a fast switching fabric, multiple packets may arrive at the same output port faster than the outgoing link can transmit them. 

• Packets are temporarily stored in an output buffer, waiting for transmission. 

• Since buffer capacity is limited, excessive queueing may cause buffer overflow and packet loss. 

• When the buffer is full, the router must decide which packets to discard: 

• Drop-tail: newly arriving packets are discarded. 

• Other policies: packets already in the queue may be removed to make room for new arrivals.

## Network Layer Routers: Buffer size

• The rule of thumb for years: buffer = average round-trip time × link capacity. A 10 Gbps link at 250 ms wants 2.5 Gbit of buffer. 

• That figure came from analysing a small number of TCP flows. With N large and independent, the requirement falls to $R T T \cdot { \frac { C } { \sqrt { N } } } .$ 

• In the core, where thousands of flows share a link, that is a very large reduction. 

• More is not better: a bigger buffer absorbs larger bursts and lengthens the queueing delay of everything inside it (bufferbloat). 

• Ten times the buffer to avoid loss can mean longer end-to-end delay — and a longer round trip makes every sender on that path slower to react. 

## Network Layer Routers: Bufferbloat Example

• Consider a single TCP flow, with no competing traffic and TCP window of 25 packets • A home router takes 10 ms to send a packet, the base RTT is 200 ms (without queueing) 

• At t = 0 a burst of 25 packets arrives at the router output buffer 

• At t = 200 ms, 20 packes have been transmitted and the first ack arrives, allowing the sender to send another packet 

• From then on, one ACK arrives every 10 ms, triggering a new packet arrival. The arrival rate matches the transmission rate 

• Result: about 5 packets remain persistently queued, adding approximately 50 ms of queueing delay without increasing throughput. 

• Bufferbloat: persistent queueing increases latency even when the outgoing link is fully utilized

## Network Layer Routers: Packet Scheduling

• When multiple packets are waiting at an output port, the router must decide which packet to transmit next. 

• This decision is made by a packet scheduling algorithm, which determines the order in which queued packets access the outgoing link. 

• Three common scheduling approaches are: 

• First-Come-First-Served (FCFS/FIFO): packets are transmitted in their arrival order. 

• Priority Queueing: packets are classified by priority, and higher-priority queues are served first. 

• Round-Robin (RR): packets are divided into different classes, and the queues are served in turn. 

• Whichever it is, a packet is removed only when it has been fully transmitted: the choice is made at the end of each transmission, not continuously. 

## Network Layer Routers: Packet Scheduling - FIFO

• One queue. Packets are selected for transmission in the same order in which they arrived at the output port. 

• If the link is busy, an arriving packet is buffered; if there is no room for it, the discarding policy decides its fate. 

• No packet can be favoured, and none can be delayed for another’s benefit. Everything on the link shares one fate. 

• Which is the reason it is the default: there is nothing to configure and nothing to get wrong.

## Network Layer Routers: Packet Scheduling – Round-robin

• In round robin queuing, packets are still sorted into classes, but classes are alternated rather than selected by priority. 

• Work-conserving: it never leaves the link idle. A class with an empty queue is skipped at once.

## Routers: Packet Scheduling – RR vs WRR vs WFQ

• Round-Robin (RR): each non-empty queue is served in turn, typically transmitting one packet per visit. 

• Weighted Round-Robin (WRR): each class is assigned a weight that determines how many packets it can transmit per cycle. 

• Weighted Fair Queuing (WFQ): each class is assigned a weight that determines its share of the output link bandwidth, taking packet sizes into account.

## Network Layer Routers: Packet Classification

## • Who decides which packets belong to each class?

• Packet scheduling algorithms are independent of the criteria used to classify traffic. 

• Network operators define classification policies based on packet header fields (e.g., IP addresses, TCP/UDP port numbers, DSCP* markings). 

• Different traffic classes can receive different priorities or shares of bandwidth. 

• Similar classification mechanisms can also be used to filter or limit specific types of traffic. 

• Net neutrality: traffic differentiation raises questions about fairness and the extent to which ISPs should be allowed to prioritize or restrict traffic. 

## Summary

• The network layer offers one service, best-effort. Order, delivery and delay guarantees are absent, and the ends built what they needed on top. 

• Forwarding is local and takes nanoseconds; routing is network-wide and takes seconds; the forwarding table is where the two meet. 

• A row is a prefix, that is a group of addresses sharing their first bits — and when several rows match, the longest one wins. 

• Three fabrics — memory, bus, crossbar. The last forwards in parallel and still cannot help two packets that want the same output port. 

• Queues form wherever a rate meets a slower one, at the input, at the output, or both; that is where the loss your senders infer is actually made.

## Introduction Network Models: The OSI Model

• In the ‘80 the ISO (International Standards Organization) defined a layered model for computer networks: the OSI (Open System Interconnection) model. 

• The ISO/OSI model includes 7 layers: 

1. Physical transmission of raw bits. 

2. Data format definition (frames). 

3. Routing of messages through the net. 

4. Transmission protocols (TCP, UDP). 

5. Management of ports and sessions (continuity of data stream). 

6. Translation of messages (encoding, compression, decryption, etc.). 

7. Data use and human-computer interaction (file sharing, emails, streaming videos, etc.). 

![image](https://cdn-mineru.openxlab.org.cn/result/2026-09-23/47ee0cc1-9c6f-41b6-ac68-39ac7a24fed9/dfdb9e516a7f53f4f680c6df5cbc05797fc37e2c7c6556944d04ceca2d1fa162.jpg)


## Introduction Network Models: The OSI Model

<sup>•</sup> Not always all layers are implemented. 

<sup>•</sup> Typically, in intermediate nodes (switches, routers), only 2 or 3 layers are implemented (media layers). 

<sup>•</sup> Only the end-points implement the whole stack up to the application layers.

## Introduction Network Models: The OSI Model

• Encapsulation (top-down): every layer of the sender adds a layer-specific field to the message (payload) in the form of a header (H) or trailer (T). 

• Decapsulation (botom-up): Those fields are removed and interpreted by the same layer in the receiver.

## Introduction OSI Model: 1. Physical Layer

• The physical layer is responsible for movements of individual bits from one hop (node) to the next. 

• Physical characteristics of interfaces and media (connectors, cables, electric signals) 

<sup>•</sup> Line configuration (point-to-point or multipoint) 

<sup>•</sup> Physical topology (mesh, star, ring or bus) 

<sup>•</sup> Transmission mode (simplex, half-duplex or duplex) 

<sup>•</sup> Representation of bits 

• Data rate 

<sup>•</sup> Synchronization of bits 

![image](https://cdn-mineru.openxlab.org.cn/result/2026-09-23/47ee0cc1-9c6f-41b6-ac68-39ac7a24fed9/21933ac6dd1c3bba6a57cdea31c30929eccc812f12177cbd3509a7a8e3a58d3b.jpg)


## Introduction OSI Model: 2. Data Link Layer

<sup>•</sup> The data link layer is responsible for moving frames from one hop (node) to the next (segment). 

<sup>•</sup> Works on frames (portion of data, typically few hundreds of bytes) 

• Flow and error control (frame control sequences) 

• Access control 

![image](https://cdn-mineru.openxlab.org.cn/result/2026-09-23/47ee0cc1-9c6f-41b6-ac68-39ac7a24fed9/00570812ef613452255df1f34b9a2576ae42ce97be6bc5fe3f8819390fffe907.jpg)


## Introduction OSI Model: 3. Network Layer

<sup>•</sup> The network layer is responsible for the delivery of individual packets from the source host to the destination host (path). 

<sup>•</sup> Works on packets (typically larger and more complex than frames) 

<sup>•</sup> Source-to-destination delivery: packets from the source to the destination. 

<sup>•</sup> Logical addressing 

• Routing (routing tables) 

![image](https://cdn-mineru.openxlab.org.cn/result/2026-09-23/47ee0cc1-9c6f-41b6-ac68-39ac7a24fed9/01ef204a6605645f20d0d45ebca74b97ac463619697f95875e971220039e1803.jpg)


## Introduction OSI Model: 4. Transport Layer

<sup>•</sup> The transport layer is responsible for the delivery of a message from one end to another (message is received by the right program). 

<sup>•</sup> End-to-end delivery 

• Connection control (Connection-oriented or connection-less) 

<sup>•</sup> Segmentation/reassembly (to/from packets of layer 3) 

<sup>•</sup> Port addressing 

• Flow and error control

## Introduction OSI Model: 5. Session Layer

<sup>•</sup> The session layer is responsible for dialog control and synchronization of request/response. 

<sup>•</sup> It establishes, maintains and synchronize the interaction between communicating system (communication session). 

<sup>•</sup> Dialog control and management

## Critique of the OSI model (1/2)

## <sup>•</sup> Bad timing

<sup>–</sup> Competing TCP/IP protocols were already in widespread use 

## <sup>•</sup> Bad design

<sup>–</sup> Both the model and the protocols are flawed 

## <sup>•</sup> Bad implementations

<sup>–</sup> Initial implementations were huge, unwieldy, and slow 

## <sup>•</sup> Bad politics

<sup>–</sup> Widely thought to be the creature of the European telecommunication ministries, the European Community, and later the U.S. Government

## Critique of the TCP/IP model (1/2)

<sup>•</sup> Model does not clearly distinguish the concepts of services, interfaces, and protocols 

<sup>•</sup> Model is not at all general 

<sup>–</sup> Poorly suited to describing any other protocol stack 

<sup>•</sup> The link layer is not really a layer at all in the normal sense of the term 

<sup>•</sup> Model does not distinguish between the physical and data link layers 

<sup>•</sup> Other protocol implementations were distributed free 

## TCP/IP vs OSI

<sup>•</sup> The ISO/OSI model is de iure the standard stack for computer networks, but it is quite complex and detailed. 

• The TCP/IP and UDP/IP (aka Internet Protocol Suite) are the set of communication protocols actually used on internet and local networks. 

• TCP: Transmission Control Protocol. 

<sup>•</sup> UDP: User Datagram Protocol. 

• IP: Internet Protocol. 

• The TCP/IP and UDP/IP are de facto the standard stack for internet communication.
